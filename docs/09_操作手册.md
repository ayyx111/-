## 一、系统简介

校园版咸鱼是一个面向高校学生的二手物品交易平台,支持商品发布、搜索、买卖、即时聊天、AI智能推荐等功能。

**访问地址:**
- 本地开发:前端 http://localhost:5173,后端 http://localhost:3000
- 线上(已部署):前端链接见 GitHub Actions → Deploy to IGA Pages → 最近一次成功 workflow 的 summary;后端 API https://resplendent-caring-production-ebd2.up.railway.app(详见 [00_项目交接文档.md](00_项目交接文档.md) 第 1.3 节)

**默认管理员账号:** admin / admin123

## 二、快速开始

### 2.1 环境准备

| 软件 | 版本要求 | 说明 |
|------|----------|------|
| Node.js | 18+ | 后端运行(本地开发必需) |
| Python | 3.11+ | AI 微服务(可选,不启动时 /ai/* 降级) |
| 数据库 | SQLite(内置零依赖) / PostgreSQL(生产 Railway) / MySQL(可选) | 通过 `DB_TYPE` 切换,开发默认 SQLite,无需另装数据库服务 |
| 缓存 | node-cache 内存缓存 | 已替代 Redis,零外部依赖 |

### 2.2 生产部署(已上线,详见 [00_项目交接文档.md](00_项目交接文档.md) 第四节)

本项目已部署,**push 代码到 GitHub main 分支即自动刷新线上页面**:
- 前端:GitHub Actions 自动构建并部署到 IGA Pages(每次 push main 触发,最新链接见 GitHub Actions → Deploy to IGA Pages → 最近一次成功 workflow 的 summary)。
- 后端:Railway 部署(含 PostgreSQL 插件),若开启了 GitHub Auto-Deploy,push 后会自动 Redeploy;也可在 Railway 控制台手动 Redeploy。
- 健康检查:后端 `GET /health` 返回 200 即正常(Railway Settings 里配置 healthcheck 路径为 `/health`)。

> 注:仓库内的 `docker-compose.yml` 为早期 MySQL+Redis 多容器编排方案,**已不再用于生产**(生产走 Railway + IGA Pages)。仅当需要本地一次性拉起全套依赖时可作为参考,但 backend 已无 Redis 依赖、默认走 SQLite,与该 compose 文件不再匹配,不建议直接使用。

### 2.3 本地开发部署(零外部依赖,SQLite + node-cache)

```bash
# 1. 启动后端(默认 SQLite 零依赖,无需另装 MySQL/Redis)
cd backend
npm install
# 本地 SQLite 还需 sqlite3 驱动(生产用 Postgres 已从依赖移除):
npm install sqlite3 --no-save
cp .env.example .env   # 确认 DB_TYPE=sqlite、DB_SYNC=true(首次建表)
npm run dev            # 启动在 http://localhost:3000,健康检查 /health

# 2. 启动前端(开发服务器自动代理 /api → localhost:3000)
cd frontend
npm install
npm run dev            # 启动在 http://localhost:5173

# 3. [可选] 启动 AI 服务(不启动时后端 /ai/* 返回 502 降级)
cd ai-service
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

## 三、用户使用指南

### 3.1 注册账号

1. 点击页面右上角【登录】按钮
2. 在登录页点击【立即注册】
3. 填写用户名、密码、邮箱/手机号、学号
4. 获取并输入验证码
5. 点击【注册】完成

### 3.2 登录系统

1. 点击【登录】按钮
2. 输入账号(用户名/邮箱/手机号/学号)和密码
3. 点击【登录】进入系统

### 3.3 校园认证(发布商品前必须)

1. 登录后进入【个人中心】
2. 点击【校园认证】
3. 上传学生证照片
4. 填写学校、学院、入学年份
5. 提交后等待审核(通常1个工作日内)

### 3.4 发布商品

1. 点击导航栏【发布】按钮
2. 上传商品图片(1-9张,第一张为封面)
3. 填写商品信息:
   - 标题(不超过30字)
   - 描述(不超过500字)
   - 分类(选择对应类别)
   - 原价和售价
   - 新旧程度
   - 交易方式(面交/邮寄/均可)
   - 交易地点
4. 点击【提交发布】
5. 等待管理员审核通过后商品上架

### 3.5 浏览和搜索商品

**浏览:**
- 首页展示所有在售商品
- 点击分类标签筛选商品
- 滚动加载更多商品

**搜索:**
- 在搜索框输入关键词
- 支持智能语义搜索(如搜"高数"可匹配"高等数学")
- 可按价格、新旧程度、学校筛选

### 3.6 购买商品

1. 进入商品详情页
2. 查看商品信息和卖家信用
3. 点击【联系卖家】沟通细节
4. 点击【立即购买】创建订单
5. 等待卖家确认订单
6. 双方线下交易
7. 交易完成后点击【确认完成】
8. 互相评价

### 3.7 即时聊天

1. 点击导航栏【消息】
2. 左侧显示会话列表
3. 点击会话进入聊天窗口
4. 输入文字发送消息
5. 支持发送图片
6. 消息实时送达

### 3.8 收藏商品

1. 在商品详情页点击【♡收藏】
2. 在【个人中心 → 我的收藏】查看收藏列表
3. 再次点击取消收藏

### 3.9 管理订单

1. 进入【个人中心 → 我的订单】
2. 切换"我买到的"/"我卖出的"
3. 查看订单状态和详情
4. 执行相应操作(确认/取消/完成/评价)

### 3.10 使用AI智能客服

1. 在个人中心点击【智能客服】
2. 输入问题(如"如何发布商品")
3. AI自动返回解答
4. 无法回答时提示转人工客服

## 四、管理员使用指南

### 4.1 登录管理后台

1. 使用管理员账号登录(admin / admin123)
2. 访问 http://localhost/admin
3. 进入管理后台

### 4.2 商品审核

1. 点击左侧菜单【商品审核】
2. 查看待审核商品列表
3. 查看商品详情和AI审核结果
4. 点击【通过】或【拒绝】
5. 审核结果通知发布者

### 4.3 用户管理

1. 点击【用户管理】
2. 查看所有用户列表
3. 可封禁/解封违规用户
4. 查看用户交易记录

### 4.4 举报处理

1. 点击【举报处理】
2. 查看举报列表
3. 核实举报内容
4. 点击【处理】或【驳回】
5. 填写处理结果

### 4.5 数据统计

1. 点击【数据统计】
2. 查看平台总览数据
3. 查看用户数、商品数、订单数
4. 查看分类分布和趋势

## 五、常见问题(FAQ)

| 问题 | 解答 |
|------|------|
| 忘记密码怎么办? | 登录页点击【忘记密码】,通过邮箱/手机验证码重置 |
| 为什么不能发布商品? | 需先完成校园认证,审核通过后才能发布 |
| 商品多久审核通过? | 通常1个工作日内,AI辅助审核加快速度 |
| 可以修改已发布的商品吗? | 在售状态可编辑,已售出不可修改 |
| 订单可以取消吗? | 待确认状态买家可取消,待交易状态需协商 |
| 如何退款? | 校园面交以线下交易为主,线上确认状态记录 |
| 账号被锁定了怎么办? | 密码错误5次锁定30分钟,等待后重试 |
| 消息发送失败? | 检查网络连接,WebSocket断开会自动重连 |
| AI推荐不准确? | 推荐基于浏览和收藏历史,使用越多越精准 |
| 如何举报违规? | 商品详情页点击【举报】,填写举报原因 |

## 六、系统维护

### 6.1 数据备份

```bash
# 本地 SQLite:直接拷贝文件库即可(后端停止时拷贝最稳妥)
cp backend/database.sqlite ./backup_$(date +%Y%m%d).sqlite

# 生产 PostgreSQL(Railway):用公共连接串导出
# 连接串见 Railway → Postgres 插件 → Connect → Public URL
pg_dump "postgres://<user>:<pass>@autorack.proxy.rlwy.net:<port>/railway" -F c -f backup.dump
```
> 注:本项目无 Redis,缓存数据无需备份(均为可重建的临时数据)。

### 6.2 日志查看

```bash
# 本地:后端/前端日志直接输出在各自 npm run dev 的终端窗口

# 生产:Railway 控制台 → backend Service → Deploy Logs(运行期)/ Build Logs(构建期)
# 前端构建日志:GitHub Actions → Deploy to IGA Pages → 对应 workflow → build
```

### 6.3 服务重启

```bash
# 本地:在对应终端 Ctrl+C 后重新 npm run dev

# 生产后端:Railway → backend Service → Deployments → 当前版本 → Redeploy
# 生产前端:push 任意提交到 main 分支,GitHub Actions 会自动重新构建部署
```

### 6.4 更新部署

```bash
# 1. 提交代码
git add <改动文件>
git commit -m "fix/feat: xxx"
git push origin main

# 2. 前端:GitHub Actions 自动构建并部署到 IGA Pages(2~3 分钟)
# 3. 后端:若 Railway 开启了 GitHub Auto-Deploy,push 后自动 Redeploy;
#    否则在 Railway 控制台手动 Redeploy
```
