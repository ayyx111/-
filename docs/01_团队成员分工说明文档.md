## 四、协作机制

### 4.1 代码协作

- **代码托管:** Git + GitHub/Gitee
- **分支策略:** main(主分支) + develop(开发分支) + feature/*(功能分支)
- **代码评审:** 所有 PR 需至少一人 Review 后合并
- **提交规范:** `feat: 新增功能` / `fix: 修复缺陷` / `docs: 文档更新`

### 4.2 沟通机制

- **日常沟通:** 微信群 / 钉钉群
- **会议频率:** 每周 2 次同步会(周一、周四)
- **文档协作:** 飞书文档 / 语雀(共享设计文档)

### 4.3 进度管理

- **任务看板:** GitHub Projects / Trello
- **里程碑:**

| 阶段 | 内容 | 周期 |
|------|------|------|
| 第1阶段 | 需求分析与设计文档 | 第1周 |
| 第2阶段 | 原型设计与环境搭建 | 第2周 |
| 第3阶段 | 核心功能开发 | 第3-4周 |
| 第4阶段 | AI功能集成与联调 | 第5周 |
| 第5阶段 | 测试、部署与汇报 | 第6周 |
