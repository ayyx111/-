## 一、架构概述

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| 前后端分离 | 前端与后端独立开发、独立部署,通过 API 通信 |
| 模块化设计 | 功能模块解耦,便于团队协作开发 |
| 可扩展性 | AI 服务独立部署,可灵活扩展 |
| 安全性 | JWT 认证、HTTPS 传输、输入校验 |
| 零依赖部署 | SQLite + Node-Cache,无需外部数据库/缓存服务 |

### 1.2 技术选型

| 层级 | 技术栈 | 选型理由 |
|------|--------|----------|
| 前端 | Vue 3 + Vite + Pinia | 渐进式框架,生态完善,开发效率高 |
| UI组件 | Element Plus | 企业级组件库,适配后台与前台 |
| 后端 | Node.js + Express | 高并发I/O,前后端同语言降低协作成本 |
| 数据库 | SQLite (better-sqlite3) | 文件型数据库,零配置部署,通过 Sequelize ORM 操作 |
| 缓存 | Node-Cache | 进程内内存缓存,零依赖,替代 Redis |
| AI服务 | Python + FastAPI | 异步高性能,AI生态丰富 |
| 实时通信 | WebSocket (Socket.IO) | 双向实时通信,聊天功能 |
| 文件存储 | 本地文件系统 | 商品图片、头像存储 |
| ORM框架 | Sequelize 6 | 多数据库支持,可平滑迁移至 MySQL |
| 密码加密 | bcryptjs | 纯 JS 实现,无需原生编译 |

## 五、安全设计

### 5.1 认证与授权

```
┌─────────────────────────────────────────────────┐
│                  安全层级                        │
├─────────────────────────────────────────────────┤
│ 1. HTTPS 传输加密                               │
│ 2. JWT Token 认证 (access: 2h, refresh: 7d)     │
│ 3. RBAC 角色权限控制 (游客/用户/管理员)         │
│ 4. 接口级权限校验中间件                         │
│ 5. 资源归属校验 (只能操作自己的资源)            │
│ 6. Node-Cache Token 黑名单管理                  │
└─────────────────────────────────────────────────┘
```

### 5.2 数据安全

| 安全项 | 措施 |
|--------|------|
| 密码存储 | bcryptjs 加密,salt rounds=10 |
| 敏感数据 | 手机号、学号脱敏显示 |
| SQL注入 | Sequelize ORM 参数化查询 |
| XSS | 输入过滤 + 输出转义(DOMPurify) |
| CSRF | SameSite Cookie + Token 校验 |
| 文件上传 | 白名单校验、大小限制(5MB)、重命名 |
| 限流防刷 | Node-Cache 计数限流(如登录接口5次/分钟) |

## 七、接口通信规范

### 7.1 统一响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "id": 1,
    "name": "示例"
  },
  "timestamp": 1786859766000
}
```

### 7.2 状态码定义

| 状态码 | 含义 |
|--------|------|
| 200 | 成功 |
| 201 | 创建成功 |
| 400 | 请求参数错误 |
| 401 | 未认证/Token失效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 资源冲突(如重复注册) |
| 429 | 请求过于频繁(限流) |
| 500 | 服务器内部错误 |

### 7.3 API 路径规范


## 九、技术风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| WebSocket 连接管理复杂 | 消息丢失 | 心跳检测 + 断线重连 + 离线消息 |
| AI 服务响应慢 | 用户体验差 | 异步调用 + 缓存 + 超时降级 |
| 图片存储占用大 | 存储成本 | 图片压缩 + OSS + CDN |
| 并发下单冲突 | 数据不一致 | 数据库事务 + 乐观锁 |
| 第三方AI API不稳定 | AI功能不可用 | 降级策略 + 本地缓存 |
